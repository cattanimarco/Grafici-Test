# Render and check Grafici examples

The Grafici-Test root is `../../..` relative to this file. Read its [README.md](../../../README.md) for the available commands. Identify the Grafici-GFX checkout being documented; do not assume the pinned submodule, a sibling folder, or the author's local paths are the desired version. Use that library's CONTRIBUTE.md for design contracts and documentation style.

## Generate pictures from the documented code

From the Grafici-Test root, run:

```sh
python3 docs/render.py --library /path/to/Grafici-GFX --sanitize
```

[docs/render.py](../../../docs/render.py) needs Python 3 and a C++11 compiler, with no Python packages. `--sanitize` requires compiler sanitizer support. Use `--output /path/to/scratch` for a preview without replacing tracked images, and `--cxx` to choose the compiler. If sanitizer support is unavailable, report that limitation separately from ordinary rendering.

The renderer extracts unique `<!-- grafici-example: NAME -->` C++ blocks from the library's README.md and CONTRIBUTE.md. It adapts hardware includes, display construction and initialization to File_GFX; plotting logic remains in the documented snippets. The examples currently share declarations from the README's first sketch. The adapter deliberately rejects unexpected setup changes rather than silently rendering different code.

For a new illustrated example, add a marker, register it in `EXAMPLES`, and update the host adapter only where its dependencies or hardware setup require it. Do not create a second handwritten copy of the plotting algorithm in the test repository. Keep unrelated gallery outputs and submodule pins unchanged.

The output is five guide PNGs today, plus a manifest under `imgs/guides/`. Follow the current `EXAMPLES` list rather than assuming that count is fixed. The manifest records the library revision, actual source fingerprint, snippet hashes, renderer hash and image hashes. Commit the generated manifest with changed images. Its Git revision alone does not capture uncommitted source changes; use the fingerprints as well when reproducing a result.

## Inspect what was rendered

Open every changed image. Check panel order, coordinate orientation, scales, color mapping, clipping and caption claims. Blank or plausible-looking pictures can still hide a bug. For changes to a boundary contract, add focused behavioral assertions as well as inspecting the picture.

File_GFX receives Adafruit GFX pixel coordinates: top-left origin, y increasing downward, RGB565 colors. The library already reverses its logical bottom-left y when emitting pixels; reversing image rows again makes the picture wrong. The PNG buffer uses RGB888, which is host storage and not a proposed Arduino framebuffer. The renderer's 640-by-480 output exercises normalized geometry at a different resolution from many physical displays.

For a rendering mismatch, check the selected library, marker extraction and host adaptation before changing the example. Separate source values and geometry from the pixel backend. Host aliases for Arduino types, random functions and `String` enable compilation; they do not establish board behavior or ABI compatibility.

## Publish within the requested scope

All guide plots must be generated by this repository. Do not paint over a wrong result, substitute an illustration, or adjust pixels separately from the code. Follow the library's documentation guidelines: short worked examples, interesting functions, visible or numerical explanations, and clear module boundaries.

When publication is requested, commit the necessary renderer/example changes, images and manifest to the appropriate branch, then push it. Use the image commit SHA in consuming Markdown, for example `https://raw.githubusercontent.com/cattanimarco/Grafici-Test/IMAGE_COMMIT/imgs/guides/beats.png`, and verify the published assets before finalizing links. A branch URL can silently change an older guide. Publishing pictures does not itself request publishing the wiki or changing a library submodule pin.

The legacy gallery uses `make` and `./unit`; inspect its includes and selected submodule before treating it as a check of an external checkout. Some revisions also contain a focused `tests/run_checks.py`; only use that command when it exists, with the intended `--library`. Neither image generation nor host sanitizers establish peak Arduino SRAM, bus timing or physical display correctness. Compile changed sketches for the actual target as a separate check.
